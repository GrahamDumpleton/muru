Daemon-managed releases write their bytecode to a directory of their own under the state directory instead of the source tree, so an immutable or read-only release directory still gets a cache and cold starts stay fast; a source that already holds compiled bytecode for the interpreter is used as it is. The `bytecode` setting, `redirect`, `source` or `off`, is in the project's `[tool.muru]` table, a declared release or `--bytecode` on `muructl deploy`.
