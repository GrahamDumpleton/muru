`muructl daemon reload` and SIGHUP now apply changes to the `[[listener]]` entries (a changed set takes a new edge, as an upgrade does, with no request lost), the `[limits]` table (sent to the edge in the snapshot, for connections accepted from then on) and the `[[events.sink]]` entries (started, stopped or restarted on their cursors), and the reload names what changed and what was done about it, what is unchanged and what is still read only at start.
