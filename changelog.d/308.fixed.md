A relative `MURU_STATE_DIR`, `MURU_CACHE_DIR`, `MURU_LOG_DIR` or `MURU_CONFIG`, or the matching `--state-dir`, `--cache-dir`, `--log-dir` or `--config`, is now taken from the directory the command runs in. Before, the runtime library unpacked under it went on the host's `PYTHONPATH` as the relative path, so under the daemon, or `muructl run --chdir`, the host could not import `muru` and exited before its workers were ready.
