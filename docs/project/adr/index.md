# Architecture decision records

Decision records capture the significant choices behind Muru, with the
context, the alternatives considered and the consequences, so that the
reasoning survives beyond the people and conversations that produced it. They
use the MADR format and are numbered sequentially. Each has a status
(proposed, accepted, deprecated, or superseded by a later record) and a date.

The records explain the choices behind the
[design specification](../design/index.md). When implementation shows that
the specification needs to change, the change is made in the same pull
request as a new record explaining why.

To add a record, copy `template.md` to the next number, fill it in, and
submit it with the change it explains. The table below is generated by the
documentation build from the records in this directory.
